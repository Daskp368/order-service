# Этап 4. Сущности JPA

## Результат

Созданы Java-сущности `User` и `Order`, а также перечисления `Role` и `OrderStatus`. Hibernate сопоставляет их с таблицами, созданными Flyway, и успешно проверяет схему в режиме `ddl-auto=validate`.

## Слои представления данных

```text
PostgreSQL                  Java
users                       User
orders                      Order
VARCHAR role                Role
VARCHAR status              OrderStatus
```

Entity представляет хранимое состояние и участвует в работе JPA. В будущих контроллерах Entity не будет возвращаться напрямую: внешний JSON-контракт представят отдельные DTO.

## `User`

| Поле Java | Колонка PostgreSQL | Тип |
|---|---|---|
| `id` | `id` | `UUID` |
| `username` | `username` | `VARCHAR(50)` |
| `passwordHash` | `password_hash` | `VARCHAR(60)` |
| `role` | `role` | `VARCHAR(20)` |

`passwordHash` хранит только BCrypt-хеш. Исходный пароль не является полем Entity.

## `Order`

| Поле Java | Колонка PostgreSQL | Тип |
|---|---|---|
| `id` | `id` | `UUID` |
| `user` | `user_id` | `UUID`, внешний ключ |
| `description` | `description` | `VARCHAR(1000)` |
| `status` | `status` | `VARCHAR(20)` |
| `createdAt` | `created_at` | `TIMESTAMP` |

`LocalDateTime` соответствует согласованному `TIMESTAMP` без часового пояса.

## Аннотации классов

```java
@Entity
@Table(name = "users")
public class User {
}
```

- `@Entity` сообщает JPA-провайдеру Hibernate, что жизненным циклом объектов этого класса нужно управлять;
- `@Table` явно задаёт имя таблицы и не позволяет полагаться на автоматическое преобразование имени класса.

Без `@Entity` класс останется обычным Java-классом и Hibernate не будет сохранять или проверять его. Без `@Table(name = "users")` Hibernate определит имя по своим правилам, которое может не совпасть с миграцией.

## Идентификаторы UUID

```java
@Id
@GeneratedValue(strategy = GenerationType.UUID)
@Column(name = "id", nullable = false, updatable = false)
private UUID id;
```

- `@Id` обозначает идентификатор Entity;
- `@GeneratedValue` поручает Hibernate создать значение;
- `GenerationType.UUID` выбирает стандартную стратегию UUID;
- `@Column` связывает поле с колонкой и описывает её свойства для JPA.

UUID генерируется приложением через Hibernate, а затем отправляется в `INSERT`. Поэтому в миграции для `id` не нужен `DEFAULT`.

## Хранение enum

```java
@Enumerated(EnumType.STRING)
@Column(name = "status", nullable = false, length = 20)
private OrderStatus status;
```

`EnumType.STRING` сохраняет имя константы, например `IN_PROGRESS`. Значение соответствует строкам из `CHECK`-ограничения миграции.

Без этой настройки JPA по умолчанию может хранить порядковый номер enum. Такой вариант опасен: изменение порядка констант меняет смысл ранее сохранённых чисел.

## Связь заказа с пользователем

```java
@ManyToOne(fetch = FetchType.LAZY, optional = false)
@JoinColumn(name = "user_id", nullable = false, updatable = false)
private User user;
```

- `@ManyToOne` задаёт отношение «много заказов — один пользователь»;
- `LAZY` откладывает загрузку пользователя до момента обращения к нему;
- `optional = false` сообщает объектной модели, что заказ обязан иметь владельца;
- `@JoinColumn` связывает поле `user` с колонкой `orders.user_id`;
- `updatable = false` не позволяет переназначать владельца обычным JPA-обновлением.

`nullable = false` — метаданные JPA, а реальную целостность базы обеспечивают `NOT NULL` и `FOREIGN KEY` из Flyway-миграции.

## Почему связь односторонняя

В `User` нет коллекции `List<Order>`. Для требований проекта достаточно ссылки `Order.user`, а список заказов пользователя позднее получит `OrderRepository`.

Отказ от ненужной обратной стороны уменьшает количество кода, исключает рассинхронизацию двух сторон отношения и снижает риск случайной загрузки большой коллекции.

Удаление заказов вместе с пользователем выполняет PostgreSQL через `ON DELETE CASCADE`, поэтому JPA-каскад для коллекции не требуется.

## Конструктор без параметров

```java
protected User() {
}
```

JPA требует у Entity конструктор без параметров с уровнем доступа `public` или `protected`. Hibernate вызывает его при восстановлении объекта из строки базы.

Для кода приложения добавлен отдельный публичный конструктор с обязательными данными. Сеттеры пока не нужны: аннотации стоят на полях, поэтому Hibernate использует field access и работает с приватными полями напрямую.

## Почему нет Lombok, `equals` и `toString`

На учебном этапе конструкторы и геттеры написаны явно, чтобы был виден контракт класса.

Автоматический `toString()` для `User` мог бы вывести `passwordHash` в лог. Автоматические `equals()` и `hashCode()` для Entity требуют отдельного решения из-за генерируемого идентификатора и изменения состояния объекта до и после сохранения.

## Неизменяемые через JPA поля

`updatable = false` установлено для данных, которые наш API не должен изменять:

- идентификаторы;
- username, хеш и роль пользователя;
- владелец, описание и дата создания заказа.

Статус заказа остаётся обновляемым — на следующем административном этапе появится контролируемый метод его изменения.

## Роль `ddl-auto=validate`

При запуске Hibernate читает метаданные Entity и сравнивает таблицы, колонки и SQL-типы с PostgreSQL. При несовпадении приложение не запускается.

`validate` не создаёт и не исправляет таблицы. Ограничения и индексы по-прежнему определяет Flyway. Кроме того, Hibernate не гарантирует проверку каждого индекса и каждого `CHECK`, поэтому миграция остаётся главным источником структуры базы.
